# Constraints

The rules in force, one file per topic, written for whoever edits the code. Each file says what the rule is, in a form short enough to read before changing the code it covers. Why a rule changed lives in the issue where the owner agreed it, linked from the file's History line.

There is no index table here, so two branches never conflict over one. The `constraints` skill builds the index from each file's `Relevance:` line.

## Format

Every file has the same parts, in this order.

- **Relevance:** when to read the file, and the paths it covers.
- **Decision:** the rule in one line of 160 characters or fewer.
- **Why:** the reason, in a few lines.
- **Rules:** what must hold.
- **Do not:** the tempting alternatives that were rejected, each with its reason.
- **Judgment:** optional. How to decide a case the rules do not cover.
- **History:** where the rule came from.
